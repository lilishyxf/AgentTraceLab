# DeepResearch Agent Harness integration

AgentTraceLab evaluates one durable run from
[`SichengLong26/deepresearch_agent_harness`](https://github.com/SichengLong26/deepresearch_agent_harness)
without changing the target repository. The reviewed source revision is
`6d9096fd859a90182a7ae2938f7741894fa071b3`.

## What is independently checked

The adapter reconstructs a framework-neutral trace from the target's `runs`, `run_events`,
`tool_calls`, `evidence`, `contract_checks`, `checkpoints`, `plans`, `tasks`, and `messages` tables.
AgentTraceLab then evaluates:

- contiguous ordering and a terminal run state;
- terminal result persistence for every recorded tool call;
- an evidence-backed `observation -> action -> validation -> replan/stop` decision chain;
- links from recovery decisions to durable tool-call IDs;
- all required completion contracts passing;
- report citations resolving to exported evidence IDs;
- checkpoint state hashes matching their stored digests;
- evidence source mode matching the Run source policy;
- reported tool-call usage matching durable tool-call rows;
- verification recovery routing, including report-repairable failures that incorrectly trigger full research replans;
- repeated verification-failure signatures, tool calls after the first misrouted replan, elapsed amplification, and tool-call amplification factor;
- credential-shaped values, event budget, and generic lifecycle rules.

The exporter opens SQLite with `mode=ro`. Raw tool arguments, tool results, and checkpoint state are
not copied into the snapshot. Tool arguments become a SHA-256 fingerprint so duplicate calls can be
detected without exposing the query. Evidence title and a bounded evidence summary are retained so
claim/evidence verification can run; snapshots must therefore be handled as evaluation data rather
than public telemetry.

The required `deepresearch.verification_recovery_routing` check distinguishes report-shaping
failures (`citation_integrity`, `claim_support`, required sections, consistency, evidence-card
coverage, and source diversity) from evidence acquisition failures. If a report-shaping failure is
routed to `replan`, the check fails and records how many later tool calls and milliseconds followed
the first misroute. `min_evidence` and `source_match` are not treated as locally repairable because
they can require new or differently scoped evidence.

## Evaluate a real local run

```powershell
agenttracelab --database-url "sqlite+pysqlite:///./agenttracelab.db" `
  evaluate-deepresearch-db "D:\path\to\deepresearch\data\app.db" RUN_ID `
  --snapshot-output "evaluation-results\deepresearch-RUN_ID.json"
```

The command is read-only with respect to the DeepResearch database. It stores only the normalized
trace and AgentTraceLab evaluation in the AgentTraceLab database.

An already exported snapshot can also be evaluated:

```powershell
agenttracelab import-deepresearch evaluation-results\deepresearch-RUN_ID.json
```

HTTP ingestion is available at `POST /v1/traces/import/deepresearch`. Replay and dataset manifests
use `"adapter": "deepresearch"`.

## Evidence recorded in this repository

`evaluation/integrations/deepresearch-harness/v1/run-snapshot.json` and the corresponding
`evaluation-report.json` were generated by
`examples/build_deepresearch_integration_run.py` using the target repository's own SQLAlchemy
repositories, then exported through the same read-only SQLite path used for real runs. It includes
one failed source-coverage observation, a replan, one completed tool call, one evidence record,
three passing completion contracts, two valid checkpoints, a passing verification, and a terminal
completion. AgentTraceLab scored that integration fixture 100/100.

The target repository's focused tests also passed locally:

- system evaluation: 2 passed;
- report safety and citation handling: 6 passed.

These are static and deterministic integration results. No `.env`, historical `data/app.db`, or
supported model/search API credential was present in the inspected clone. Therefore this repository
does **not** claim a live DeepResearch success rate, retrieval improvement, latency distribution, or
model-quality gain yet. Those numbers require a versioned task set and repeated live runs.

## Run the repeated live benchmark

Start the target API with a configured model/search provider and migrated SQLite database. Then run:

```powershell
agenttracelab --database-url "sqlite+pysqlite:///./agenttracelab.db" `
  run-deepresearch-benchmark `
  "evaluation/benchmarks/deepresearch/v1/manifest.json" `
  --base-url "http://127.0.0.1:8000" `
  --source-database "D:\path\to\deepresearch_agent_harness\data\app.db" `
  --output-directory "evaluation-results\deepresearch-v1-live-001"
```

The runner creates a new Session for every trial to prevent memory leakage between repeats. It
stores three immutable artifacts per trial (`run-snapshot.json`, `normalized-trace.json`, and
`evaluation-report.json`) plus an aggregate JSON report and Markdown summary. Use a new output
directory for every benchmark execution.

When a trial exceeds `timeout_seconds`, the runner requests cancellation and waits up to the
manifest's `cancel_grace_seconds` (30 seconds by default) for a terminal target state. It then makes
a best-effort read-only export of the cancelled or failed Run and writes the same snapshot, trace,
and deterministic evaluation artifacts. The trial remains failed with the original runner error;
diagnostic capture never converts a timeout into a pass and does not invoke the external Claim
Judge. If export itself fails, the aggregate retains both the original error and a bounded capture
failure message instead of aborting the remaining benchmark.

When evaluator rules change, reapply them to the retained immutable snapshots without spending
model or search calls again. Keep the rescored report beside the original so relative artifact links
remain valid:

```powershell
agenttracelab rescore-deepresearch-benchmark `
  "evaluation-results\deepresearch-v1-live-001\benchmark-report.json" `
  --report-output "evaluation-results\deepresearch-v1-live-001\benchmark-report-rescored.json"
```

The included v1 manifest contains four process-oriented research tasks and runs each three times.
The aggregate distinguishes:

- completion rate from evaluation pass rate;
- Pass@1 from Pass^k (all k repetitions must pass);
- mean score from the 95% Wilson lower confidence bound;
- deterministic trace/citation integrity from claim-level factual correctness.

The runner intentionally cannot infer whether a target uses a real model or a mock. The manifest's
`evidence_class` is therefore part of benchmark provenance and must be set honestly. Even a
`live-system` result is not a factual-quality result until claim/evidence grading and human or
independent Judge calibration are added.

The full staged workflow, fault suite, and regression-loop commands are documented in
[`deepresearch-evaluation-loop.md`](deepresearch-evaluation-loop.md).
